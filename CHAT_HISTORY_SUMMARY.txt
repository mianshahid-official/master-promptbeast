1. PROJECT GOAL & USER DIRECTIVES
--------------------------------------------------------------------------------
PromptBeast is an AI video production studio designed for long-form narrations
and story-driven content. The core workflow allows a creator to:
  Step 1: Load voiceover audio (.mp3, .wav) and word timestamps (.json).
  Step 2: Paste custom storyboard breakdowns (Visual 1 Words: ... Visual: ...).
  Step 3: Load or paste structured production bibles (Story, Character, Environment, Props, Style).
  Step 4: Select from curated Visual Art Styles (each with a dedicated Master AI Prompt).
  Step 5: Review storyboard & proceed to Studio for Groq prompt expansion, then Gemini image generation and FFmpeg video assembly.

Key Constraints & Rules:
- FrameForge Red & Black visual styling: deep blacks (#0D0D0D, #121212, #171717),
  dark borders (#222222, #2E2E2E), and vivid FrameForge red accents (#E53935, #FF4B4B, #B71C1C).
- No unprofessional borders around text fields or headers.
- Single unified next button across every step in the pipeline.
- Do NOT auto-load placeholder speech.wav or speech.json on startup.
- Complete removal of thumbnails feature (user handles thumbnails manually).
- Complete removal of separate Scene Sync tab / options across the app.
- Core pipeline functionality, Groq prompt generation, and Gemini image downloading must remain 100% operational.

5. ISSUE DIAGNOSIS & CODE CORRECTIONS
--------------------------------------------------------------------------------
Issue 1: Window showed "(Not Responding)" upon clicking Next button.
Root Cause:
- Redundant cascaded event signals:
  `self.visual_scenes_aligned.emit()`, `self.proceed_to_studio_requested.emit()`,
  and `self.navigate_requested.emit()` were firing simultaneously.
- `_on_sidebar_nav_changed` and `_on_workflow_scenes_aligned` both triggered
  `prompt_grid.load_scenes(scenes)` 3 to 4 times synchronously.
- Inside `prompt_grid.py`, `load_scenes()` lacked an idempotency check, causing
  repeated widget teardown and rebuilding of 100+ nested card widgets on the GUI thread,
  temporarily blocking the Windows event loop.
Fix:
- Followed clean implementation pattern from `D:\AntiGravity\script-beanie-main.zip`:
  1. In `NarrationWorkflowPanel._on_proceed_to_studio`:
     - Synchronize scenes and bibles cleanly.
     - Single signal emission to `navigate_requested.emit("studio")`.
  2. In `PromptGrid.load_scenes`:
     - Add identity check: if `self.scenes == scenes and len(self._card_widgets) == len(scenes)`, return immediately.
  3. In `MainWindow._on_sidebar_nav_changed("studio")`:
     - Synchronize project state scenes if not set.
     - Load prompt grid scenes once.
     - Display plan approval banner.
     - Set stacked page to Studio.

Issue 2: Duplicate Step 4 Header.
Root Cause:
- `StyleThumbnailMatrix` had an inner header QLabel alongside the parent card header.
Fix:
- Removed inner title label, leaving only the single card header and active style badge.

Issue 3: Step 2 Alignment Button Removal.
Fix:
- Removed manual parse button from layout.
- Added live 300ms debounced auto-sync on `txt_visual_ideas.textChanged`.

Issue 4: UI Hang When Pasting Storyboard & IndexError: list index out of range on Next button.
Root Cause:
- `align_visuals_with_timestamps` in `app/core/narration_workflow.py` used nested quadratic `difflib.SequenceMatcher` loops (560 iterations per scene x 26 scenes = 14,560 string comparisons), locking the GUI thread for 10-15 seconds and causing Windows to report "(Not Responding)".
- When `curr_w_idx` reached or exceeded `len(words)` (e.g. when audio had fewer words than the storyboard, or on mismatched scripts), `best_start` evaluated to `len(words)` and raised `IndexError: list index out of range` on `words[best_start].start`.
- This unhandled crash prevented `self.scenes` from being created. When the user clicked Next, it attempted to re-run alignment, hung again, crashed with `IndexError`, and failed to transition to Studio.
Fix:
- Replaced the quadratic `SequenceMatcher` algorithm with an ultra-fast O(N) token-prefix and set-overlap matching engine (< 40ms for 26 scenes on 1800 words vs. 12+ seconds previously).
- Added defensive index safety guards: `best_start` and `end_idx` are clamped to `[0, num_words - 1]`. If words are exhausted, timestamps are smoothly extrapolated from the preceding scene's end time.
- Wrapped `_auto_sync_storyboard` in defensive try/except fallback logic to prevent uncaught exceptions.

Issue 5: Prompt Cards in Studio Stuck on "[Planned Visual Shot - Awaiting Batch Prompt Gen]" and Approval Banner Reset.
Root Cause:
- `PromptGrid.load_scenes()` had an early exit `if hasattr(self, "scenes") and self.scenes == scenes and len(self._card_widgets) == len(scenes): return`. Since Groq expansion updates `.prompt` on the same `VisualScene` instances in place, `load_scenes()` skipped rebuilding cards.
- Navigating to the Studio tab in `_on_sidebar_nav_changed` unconditionally reset `self.plan_summary_lbl` to "Review your scenes below, then click Approve to expand prompts via Groq" and the button to "✓ Approve Plan and Expand Prompts", overriding the completed generation state.
Fix:
- Modified `PromptGrid.load_scenes(scenes, force=False)` to check if prompt texts have been populated/changed and added `force=True` on job completion.
- Updated Studio navigation logic to inspect whether scenes already contain expanded prompts (`has_prompts`); if so, it displays `"✓ {num} Prompts Expanded & Ready!"` with a red button `"➔ Next Step: Generate Images (Go to Images)"`.

Issue 6: Lingering Green/Slate Colors Across Studio, Images, and Deliverables.
Fix:
- Replaced all lime green (`#A3FF12`, `#B8FF24`), emerald/mint (`#34D399`, `#10B981`, `#4ade80`), and cyan badges/borders with FrameForge Red (`#E53935`, `#FF4B4B`, `#1F1515`) and neutral dark slates (`#181818`, `#282828`).
- Subtitle preset buttons, color pickers, and live preview box are now styled in FrameForge Red and dark charcoal.

Issue 7: Dynamic Karaoke Spoken Word Zoom (Hormozi / MrBeast Pop).
Fix:
- In `app/core/subtitle_engine.py`, modified ASS subtitle generation to emit Dialogue events per active spoken word with `{\\fscx130\\fscy130\\c{highlight_ass}}` for the spoken word (enlarging it to 130%), and `{\\fscx100\\fscy100\\c{base_ass}}` for surrounding inactive words.
- In `app/ui/widgets/subtitle_editor.py`, updated the live preview to render the active word at 130% size with bold underline.

Issue 8: Random Transitions Between Images in Video Render.
Fix:
- Added `TransitionStyle` enum in `app/models/video_config.py` (`RANDOM`, `DIP_TO_BLACK`, `CROSSFADE`, `CUT`).
- In `app/core/video_renderer.py`, applied dynamic random transitions (dip to black, soft fade, subtle white flash) inside each scene segment filter, preserving frame-accurate audio and subtitle synchronization.
- Added transition selector in Deliverables tab (`render_panel.py`).
